# AI 문체 점검 목록

박현우 교수님이 제공한 참고용 점검 목록이다. 필수 집필 기준과 PR 리뷰의 구분은 [WRITING_STYLE.md](WRITING_STYLE.md)를 따른다.

학생은 초안 PR을 제출하기 전에 이 목록을 참고해 자기 원고를 점검한다. 반복되는 표현이나 불필요한 문장을 살피되, 개별 단어가 있다는 이유만으로 삭제하지 않는다. 사실, 필요한 조건과 불확실성, 저자의 주장과 목소리를 보존한다. 이후 교차리뷰와 장 단위 문체 편집에서도 같은 목록을 참고한다.

PR 제출 절차는 [CONTRIBUTING.md](../CONTRIBUTING.md), 에이전트 작업 지침은 [AGENTS.md](../AGENTS.md), 문서 전체 안내는 [docs/README.md](README.md)에 있다.

아래는 교수님이 제공한 원문이다.

내가 원고나 슬라이드를 AI와 같이 쓸 때 쓰는 점검 기준을 책 원고에 맞게 추렸다. 그대로 따를 필요는 없다. WRITING_STYLE.md를 보완하거나 나중에 톤을 맞출 때 쓸 만한 것만 골라 쓰면 된다.

## 1. 기계로 바로 잡을 수 있는 것

- 긴 대시(em dash, U+2014)는 쓰지 않는다. 원문을 그대로 옮긴 인용만 예외다. 문장을 나누거나 쉼표, 콜론, 괄호를 쓴다.
- 한글 단어 사이의 가운뎃점(U+00B7)은 쓰지 않는다. "A와 B"나 "A, B"로 쓴다.
- 반각 대시(en dash, U+2013)는 숫자 범위에만 쓴다.
- 본문에 이모지를 넣지 않는다.

## 2. 문장 패턴

- **조건 대구.** "X했다면, Y한다", "X를 넘어 Y로", "X가 아니라 Y다"를 되풀이하는 문장. 하고 싶은 말을 평서문으로 쓴다.
  - 예: "지난주에 이해했다면, 이번 주는 만든다" → "이번 주에는 지난주에 배운 개념으로 직접 만들어 본다."
- **은유 제목.** "~의 문법", "~의 심장", "~를 향한 여정" 같은 제목. 제목에는 다루는 내용을 그대로 적는다.
- **표어식 소제목.** "학교가 모든 아이에게 준다" 같은 구호 대신 "수업 시간 안에서 실시"처럼 내용을 적는다.
- **셋씩 나열하는 버릇.** 항목이 둘이면 둘만 쓴다.
- **마무리 경구.** "단순한 도구가 아니라 동반자다", "코드는 사라지고 의도만 남는다" 같은 한 줄로 문단을 닫지 않는다.
- **평범한 자리의 센 동사.** 문장을 생생하게 만들려고 고른 구어 동사는 AI 티가 난다. "공고에 박혀 있다"는 "공고에 그렇게 되어 있다"로, "~와 바로 붙는다"는 "~에 해당한다"로 쓴다.
- **동의어 돌려쓰기.** 같은 대상을 문단마다 다른 말로 부르지 않는다. 한 번 정한 용어를 계속 쓴다.

## 3. 어휘

- 한국어: 혁신적인, 패러다임, 게임 체인저, 눈부신, 여정, 대장정, 무한한 잠재력, 새로운 지평.
- 영어: delve, tapestry, a testament to, not just ... but, more than just, landscape, pivotal, seamless, unlock.

이 단어들을 쓰면 안 된다는 뜻은 아니다. 근거 없이 분위기만 올리는 자리에 들어가 있으면 뺀다.

## 4. 내용 패턴

- **의미 부풀리기.** "~의 역사에 중요한 전환점이 되었다" 같은 평가를 근거 없이 붙이지 않는다.
- **흐릿한 출처.** "전문가들은", "많은 연구에 따르면". 누가 어디서 말했는지 쓰거나 문장을 뺀다.
- **의례적인 한계와 전망.** 모든 꼭지 끝에 "과제와 전망"을 붙이지 않는다. 쓸 내용이 있을 때만 쓴다.
- **뻔한 긍정 결론.** "앞으로의 발전이 기대된다"로 끝내지 않는다. 마지막 문장은 그 꼭지의 실제 결론이다.
- **예고 문장.** "이 절에서는 ~을 살펴보고자 한다", "이제 ~에 대해 알아보자". 바로 본론으로 들어간다.
- **과한 헤지.** "~할 수 있을 것으로 보인다". 불확실하면 무엇이 왜 불확실한지 한 번만 쓴다.
- **채팅 흔적.** "좋은 질문입니다", "도움이 되었길 바랍니다", "제 지식 기준으로는". 원고에 남아 있으면 지운다.

## 5. 서식

- 굵은 글씨는 꼭 필요한 곳에만 쓴다.
- "**항목:** 설명" 형태의 목록으로 설명 문단을 대신하지 않는다. 설명은 이어지는 문단으로 쓴다(WRITING_STYLE.md 4절과 같다).

## 6. 점검하는 방법

1. **기계 점검.** 1절은 grep으로 잡는다.
   ```bash
   grep -nP '\x{2014}|(?<=\p{Hangul})\x{00B7}(?=\p{Hangul})' ko/sections/*.qmd
   ```
2. **AI에게 되묻기.** 고친 원고를 주고 "이 글이 AI가 쓴 것처럼 보이는 이유를 짧게 꼽아 줘"라고 묻는다. 꼽힌 곳만 고치게 하고 나머지 문장은 건드리지 않게 한다.
3. **소리 내어 읽기.** 저자가 말로는 하지 않을 문장이면 고친다.
4. **목록 늘리기.** 리뷰에서 걸린 표현은 이 목록에 추가한다. 같은 지적을 두 번 하지 않으려고 내가 쓰는 방법이다.

이 목록을 통과했다고 좋은 글이 되지는 않는다. 내용과 저자의 목소리가 먼저다.
